做中文产品时，我经常看到这样的正文样式：`font-size: 14px; line-height: 1.5`。它在设计稿里看起来整齐，在真实屏幕上却总觉得挤。

问题通常不在 1.5 本身，而在于这个比例是从一套西文字体的经验里借来的。

## 汉字占满了字身框

西文字母大多没有填满 em box。字母 x 的高度、上伸部和下伸部共同构成了视觉重心，行与行之间天然留出了空白。

汉字的字面率要高得多。一个“国”字几乎填满整个方块，字与字之间的视觉密度更接近实心。同样的字号和行高，中文段落的墨色会更重，行与行的距离也更紧。

所以，中文正文通常需要比西文更大的行高倍数。不是因为它更“难读”，而是因为它的字形结构需要更多呼吸。

## 19px 正文不是过度设计

我偏好在长文阅读页使用 18–19px 的正文，行高 1.8 左右。这个组合不适用于所有界面：

- 密集的数据表格可以更紧，因为阅读方式是扫视而非连续阅读。
- 导航和标签使用 1.2–1.4 的行高即可，它们通常是单行。
- 正文、引用和说明文字需要更舒展，因为它们承载连续的句子。

关键不是记住某个数字，而是区分阅读模式。扫描和阅读对密度的需求不同，界面不能用一套行高覆盖所有场景。

```css
.article-body {
  max-width: 44rem;
  font-size: clamp(1.0625rem, 0.95rem + 0.25vw, 1.1875rem);
  line-height: 1.85;
  letter-spacing: 0.01em;
  text-wrap: pretty;
}

.article-body p + p {
  margin-block-start: 1.5em;
}
```

这里的 `max-width: 44rem` 并不是一个神圣的宽度。中文每行 30–38 个汉字通常比较舒适，具体数值还取决于字号、字重和页面环境。需要避免的是让文字铺满整个宽屏。

## 行距和段距要分工

行高负责同一段落内的节奏，段距负责段落之间的关系。两者被混为一谈时，段落会失去边界。

我通常让段距保持在行高的 0.8–1.2 倍之间。段距太小，段落会糊成一片；段距太大，文章又会变得像一堆孤立模块。

标题周围的空白也需要单独考虑。标题的字号越大，它和下一段之间需要的间距通常越多；但它和上一节之间的间距又应该明显大于它和正文之间的距离。这个不对称是层级成立的关键。

## 不同的中文字体也会改变答案

系统字体栈里的苹方、思源黑体、微软雅黑，字面率和字形比例并不相同。同一段文字在 Mac 和 Windows 上的密度会有差异。

所以行高不能只在设计工具里看。上线前至少要在真实浏览器里检查一次长文：最长的一段、包含英文和标点的混排、带链接的句子、以及行尾标点。

另外，中文的标点和拉丁字母混排时，字距往往需要额外微调。不要为了“整齐”给所有文字加宽字距；英文单词会被拉散，数字会失去节奏。应当针对正文的混排环境做小幅、整体的调整。

## 从一行开始

如果只能做一件事来改善中文阅读，我会先调行高，而不是字号。

把正文放大到 18px，行高调到 1.8，行宽控制在 36 个汉字左右。你会立刻发现，文字并没有变得更“大”，但阅读开始有了节奏。那一口气，终于匀了。
